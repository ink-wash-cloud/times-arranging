# 多语言（i18n）约定

时序现在支持 **简体中文 / 繁體中文 / English / 日本語**。
语言是这台设备的偏好，存在 `Config.lang`，**不跟着服务器同步**。

## 一句话规则

**把界面上的中文字面量包进 `t()`，一个字都不许改。**

    <h3>今日待办</h3>            →  <h3>{t('今日待办')}</h3>
    title="点击同步"              →  title={t('点击同步')}
    toast('已保存', 'ok')         →  toast(t('已保存'), 'ok')
    return '还有 ' + n + ' 天'    →  return t('还有 {n} 天', { n })

**为什么原文不能改**：字典的 key 就是简体原文，而且现有自动化测试（33 套）断言的
也是这些简体字符串。改一个字，词典对不上、测试也红。

## 硬性规定（踩过坑的）

1. **绝不能把 `t()` 写在模块顶层常量里。**
   ```ts
   const NAV = [{ label: t('今日总览') }]   // ✗ 错：模块在 boot() 之前就求值了，
                                            //   那时语言还是默认值，切语言不会变
   const NAV = [{ label: '今日总览' }]        // ✓ 对：存原文，渲染时 {t(n.label)}
   ```
   同理：`useMemo` 里可以，`useEffect` 里可以，函数体里可以。

2. **带变量的句子用 `{name}` 占位符，不要用 `+` 拼。**
   ```ts
   t('已选 {n} 个 · 共 {total} 分钟', { n: 3, total: 45 })
   ```
   语序、量词、有没有空格都在译文里解决。占位符名只允许 `\w+`。

3. **繁体不用管**：`t()` 会自动用 `src/lib/i18n/s2t.ts` 的字表把简体转成繁体。
   只维护简体 + 英/日两份词典。**不要写繁体字面量**。

4. **拼装型格式**（日期、时长这类不是一句完整话的）用 `src/lib/date.ts` 的
   `pick(简, 繁, en, ja)`，不要塞进词典。`fmtCN / relativeDay / fromNow / humanMinutes`
   已经改好了，直接调用。

5. **通知文案**：系统通知是"排程时写进系统、到点才弹"的，如果用户在中间切了语言，
   已经排好的那条还是旧语言——这是可接受的。但**排程时**要用当前语言：
   `t()` 即可；如果某处明确知道语言变量，用 `tIn(lang, '…')`。

6. **词典文件按领域分**：`src/lib/i18n/dict/{core,tt,tasks,settings,libs}.ts`，
   每个文件里都是 `export const en = { '简体原文': '译文' }` 和 `ja`。
   **只写自己负责那一份**，别去改别人的，也别改 `dicts.ts`。

7. **找不到译文时自动回落到简体原文**，界面不会空白。所以宁可先覆盖率 90%，
   也不要把译文写错。检查覆盖率：
   ```
   node scripts/check-i18n.mjs            # 统计
   node scripts/check-i18n.mjs --missing  # 列出缺失的原文和所在文件
   ```

## 动手前

- 构建：`$env:TEMP=(Resolve-Path .tmp).Path; $env:TMP=$env:TEMP; npm run build:lock`
  （`build:lock` 会排队，几个人同时构建不会把 dist 弄坏）
- 类型检查：`npx tsc --noEmit -p tsconfig.json`
- 别碰：`src/lib/i18n/index.ts`、`dicts.ts`、`s2t.ts`、`src/styles.css`、
  `src/lib/date.ts`、`AGENTS.md`、`src/lib/changelog.ts`、`package.json` 的版本号。
- 别跑 `npm run release`，也别改版本号——发版由 Lead 统一做。
- 本地起服务测试请用 8810–8899 之间的端口，别占用 8787（那是用户正在用的）。
